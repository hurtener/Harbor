# Retained dispatch durability checkpoint

RFC 002 / phase 269; incremental implementation, not RC acceptance.

Enabled served root runs and embedded runs persist the admitted query before
inference. The run loop then requires a committed intent before dispatch and a
committed permitted result/error before dependent inference. The existing
StateStore `SaveBatchIf` atomically writes one action frame and its small head.
Prior frames are not rewritten as the trajectory grows. No backend, service,
provider SDK, native compaction, or long-term-memory feature is introduced.

A journal is run-scoped and admission-bound. Writes compare the current session
window generation, run-head generation, frame generation, and existing session
erasure fences. In-flight sibling journals are not automatically projected into
another run. A pending frame means the outcome is unknown, never that an
external write failed. A parallel batch is one exchange; partial branch
execution remains uncertain until the aggregate result is committed.

Persistence failures terminate execution; they are not fed to the model as a
tool error that it might repair by repeating an external action. A returned
outcome is persisted with a bounded cancellation-independent context after the
executor goroutine has joined. The dispatch-count callback follows settlement,
so a counter failure cannot erase an already observed receipt. Required
persistence does not occur under the trajectory inspection mutex.

The journal shares the existing 256-exchange and 512-KiB bounds. Oversized
indivisible evidence fails explicitly, without clipping it. Runtime metadata
is not generated by the model; content passes through the configured redactor.
Terminal publication seals the journal and updates the bounded session window
atomically. Exact-generation cleanup then removes transient frames and the
head. Cleanup failures remain explicit; no action is retried. Session erasure
also removes these private run records.

The request-level regression fails on the preceding terminal-only source.
The new checks cover pre-dispatch intent, pre-inference exact settlement,
failure before and after an external action, SQLite close/reopen with pending
and settled frames, isolation, bounds, and cleanup. Deterministic fixtures prove
runtime ordering and representation, not real-model proficiency.

This checkpoint does not enable automatic cold execution or interrupted-prefix
reuse. An interrupted admission stays fenced from ordinary reacquisition.
Authorized reconciliation, native historical projection/checkpoint reuse,
large-result recovery, and remaining full-repository release gates are still
required before declaring the whole phase complete.

## Approval-bridge failure correction

A joined executor's returned outcome must also survive a simultaneous approval
bridge failure. The run loop now records and settles that outcome before
returning the original control error; it still cannot advance to another
decision or action. If settlement itself fails, both errors remain discoverable
through the error chain. No approval decision is relaxed or bypassed.

The regression uses the real approval gate, closes it during an in-flight
dispatch, and returns an acknowledgement while the executor unwinds. It failed
before the correction because the outcome was discarded. Cancellation and
dispatch-counter failures additionally assert that exact receipts reach
settlement, identity is preserved, persistence has a bounded live context, and
the inspection mutex is not held.
